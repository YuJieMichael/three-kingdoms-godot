## 目标

用户选择持久世界 PvP 为主方向，先验证 2～4 个独立账号的共享地图、出征、援军、自动结算和返程。保留建设、兵种、射程和进退规则。四个虚构演练账号预置兵力、两组联盟与有效战争状态，所有结算仍由原规则完成；这不是正式服务器的新手礼包或平衡调整。

## 验收

- [x] 原网页仓库、Pages、vendor/legacy 与用户现有进度保持不变；新增规则快照注明来源和摘要。
- [x] 四账号拥有各自鉴权、进度和稳定的权威身份；读取与命令只返回本账号私有数据，公共地图不泄露敌方军队、资源或令牌。
- [x] 共享命令串行、版本检查、原编号重试和多方原子持久化生效，重启不重复扣兵、战损、缴获或返程入库。
- [x] 服务按服务器时间自动处理抵达、援军驻扎、战斗和返程；玩家下线不要求手动确认，客户端不能上传结果或快进时间。
- [x] Godot 可查看玩家城池及关系，派兵攻击、支援盟友、召回援军，显示行军时间与参与者一致的战报。
- [x] 共享与私人模式、账号身份及待确认操作明确隔离，连接中断或版本冲突后可安全刷新；共享世界禁用私人存档导入导出。
- [x] 完成有实际状态断言的 HTTP 回归、Godot 客户端检查与真实原生/Web 多账号攻防观察；保存截图和结果边界。
- [x] 提供可直接启动的独立演练入口和操作说明，原生与 Web 导出通过；公开部署、Steamworks、百人负载和 Windows 实机多人测试分别报告。

## 边界

采用 CCGS minimal dev-story → story-done，依据本故事验收和 game-brief 实施；无 TR registry、控制 manifest 或新增治理 ADR，省略相应材料。因涉及多账号资产、断线重试和持久化，编写有意义的集成检查；不因 minimal 而以只读源码代替真实启动。

本轮共享服务仅绑定 loopback，凭据与演练存档置于独立私有目录。没有公网账号、收费项目、Supabase 部署、Steam ID 或 SDK 配置。不增加渡口通路控制、联盟联合计划、分阶段攻城或新的名将技能；这些设计在本轮闭环验证后推进。
