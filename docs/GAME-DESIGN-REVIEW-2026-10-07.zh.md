# Godot 版本的设计建议与本轮修改

基线：`5dd271a`，`0.6.0-dev.12`。本轮阅读现有客户端、规则投影和仓库已有截图；没有将历史截图视为本轮运行结果。

## 方向

建议把首局体验集中在「建设 → 配兵掠夺 → 获得物资与俘将 → 回城培养」这条循环。现版本已有首战30弓、侦察、成长路线、战后收支、城景成长和减少动态效果，应继续让这些系统相互连接。

本轮主要采用 `game-design-theory`、`game-ui-design`、`game-ui-ux` 和 `game-feel` 的指引：重要信息先显示，复杂资料按需展开，选择与消费分开，操作后给清楚反馈。项目继续使用 Godot 和原有权威规则；Web/Three.js、Higgsfield 建站和多人架构技能仅在对应任务需要时使用。

## 已落实

| 修改 | 玩家能看到什么 | 实现 |
| --- | --- | --- |
| 背包分类格子 | 已持有物品的名称、数量和选中标记；窄屏2列、宽屏3列，保留分类搜索 | `src/inventory_dialog.gd` |
| 城内、城外键盘选格 | Tab 聚焦、方向键选择、Enter 打开原预览；明显焦点框和滚动跟随 | `src/city_view.gd`、`src/suburb_view.gd` |
| 操作提示与消息记录 | 普通提示约5秒、需留意的提示约7秒；「消息」可查看最近30条完整文字 | `src/notification_center.gd`、`src/main.gd` |
| 战利品与俘将 | 真实道具、珠宝、装备、野将、声望及容量不足的弃置记录；直接进入相关管理页 | `src/report_loot_view.gd`、`src/main.gd` |
| 成长建议完整显示 | 礼包、可领取任务奖励和资源恢复建议优先显示，剩余建议不再被两条上限截断 | `src/growth_route_view.gd` |

格子选择和 Enter 都只查看原有详情；消费仍走既有报价与确认。消息只存在于内存，切换账号／进度后清空；请求未确认时不把提示误称为操作失败。战报显示的是当时结果，缺字段显示「未记录」，不能将已招降的历史俘将描述为当前仍待招降。

## 下一步建议，按优先级

1. **配兵的取舍更清楚。** 在兵种数量旁显示实际射程、速度和定位；报价突出最慢兵种与运力。`src/dispatch_dialog.gd` 当前主要显示名称和可用人数，`bridge/dto.mjs` 已有兵种属性，原规则按最慢兵种决定行军速度。先改善决策信息，再考虑新技能。
2. **掠夺目标对应资源缺口。** 玩家缺石料时，应能从合法公开的战前报价判断哪些目标可能补足缺口，以及运力能装多少。沿用 `attackInfo`、`lootPreview`、`carry`，不显示隐藏守军或未经计算的胜率。
3. **抓将前看筹备条件。** 购买画像前展示权威规则确认的爵位、黄金／珠宝与房间容量要求。当前画像与招降报价分在抓将前后；增加只读投影可以减少「抓到了却养不起」的无意挫败。
4. **手机战斗显示当前军令。** 在选中兵队旁明确标出前进／固守／后退和指定目标；在现有目标参数基础上提供修改入口，保留回合结算。
5. **战后接回下一次出征。** 在已有补兵、治疗预算旁提供「查看伤兵」「前往训练」「当前成长目标」入口，减少切页寻找；治疗和训练仍需玩家确认。

- 本机 Godot `4.7.2.stable.official.ed1daf0bf`；安装包 SHA512 与官方校验文件一致。

- 没有添加或运行功能测试，没有进行本轮桌面、浏览器、实体手机或手柄试玩，也没有重新导出或发布游戏包。键盘选格与滚动、格子窄屏布局、消息浮层位置仍需实际设备确认。
