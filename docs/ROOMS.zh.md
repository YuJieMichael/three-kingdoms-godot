# 1–8人房间试玩

本地0.5.0新增创建房间、邀请码加入与自己的城池恢复。每房间有独立世界、服务器生成的城主身份和进度，最多8人。当前仅接受本机连接；真实跨电脑账号、Supabase及Steamworks尚未接入。

## 运行

Windows包完整解压，先打开 `StartRooms.cmd` 并保持服务窗口运行，再打开 `PlayRooms.cmd`。桌面联机大厅可创建、加入或恢复。

网页包完整解压，在Windows打开 `StartRooms.cmd`；macOS/Linux安装Node后运行 `./start-rooms.sh`。大厅为 http://127.0.0.1:17343/lobby 。不能直接双击HTML文件。

源码运行：

```sh
node scripts/start-rooms.mjs --port 17343 --data-dir .local/rooms --web-dir build/web
```

原生客户端使用：

```sh
node scripts/start-rooms.mjs --native-only --data-dir .local/rooms
TK_NODE=/path/to/node godot --path . -- --lobby=http://127.0.0.1:17343
```

## 创建、加入与返回

1. 创建房间时填写房间名、人数上限和自己的城主名。上限为1–8人。
2. 将邀请码交给其他城主。邀请码只申请空席位，不能进入已有城主的城池。
3. 创建或加入成功后，自行保存房间编号和自己的恢复密钥，再进入游戏。密钥仅自己保存。
4. 关闭或刷新后，选择恢复城池，填写房间编号与自己的密钥。即使满员，也能返回原席位；恢复不会新建城池。

创建、加入若未收到可靠确认，保持窗口开启，使用原请求重试。重试不会多建城池。**未确认的登记请求只保存在当前窗口内；关闭或刷新会丢失这份重试信息，可能无法找回已创建的席位。** 放弃重试不会撤销服务器可能已经创建的席位。游戏内命令回执继续使用原有持久重试机制；这与大厅登记的内存重试不同。

## 攻守演练

每位城主有同样的预置资源与兵力：600轻骑、500弓箭、300长枪。加入时按席位交替分入青、赤两盟，默认已结束保护并交战。预置兵力是演练配置，不是正式新手礼包。联盟之后可变化，支援和出征以当前联盟关系为准。

共享战争显示当前房间的城池、盟友/敌方、行军到达时间、驻扎与战报。向盟友派遣援军后到时驻扎；可召回，返城自动归队。向敌城掠夺时立即扣除出征兵力与粮草，抵达自动交战，返回后缴获实际入库。主城不能占领。攻击方、守方查看同一份自动战报，真实守军与已抵达援军参与结算。

## 保存与限制

- 房间、私人试玩与原四账号演练各使用独立目录。不要把旧存档目录用于另一种启动入口。
- 房间的成员、身份、世界、战斗及回执在同一原子保存中提交。服务重启后仍使用原世界；损坏文件不会自动覆盖。
- 邀请与恢复凭据不自动写入客户端配置，进入游戏的令牌不留在URL查询参数。客户端自行保存恢复密钥，不提供正式账号找回功能。
- 当前是同一电脑的浏览器/桌面多客户端演练。跨电脑公开服务、真实账号、百人负载、Windows人工长局和Steamworks需后续验证与配置。

原网页和原GitHub仓库保持不变。0.5.0目前为本地包，公开发布仍为0.3.1。
